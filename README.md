# 外部记录采集台：来源授权 · 下载 · 内容共享缓存

纯 Python 标准库实现（无第三方依赖）。演示"外部记录带附件链接、内容可替换、授权可撤回"
场景下的采集、缓存与访问控制，所有附件均为程序生成的样例内容。

## 组成

```
source_server.py     慢速外部来源服务（生成样例附件、授权/撤权、内容替换）
collector/           采集端
  ├─ app.py          HTTP 服务：采集页 + JSON API + 预览/下载入口
  ├─ core.py         核心逻辑：授权同步、下载、撤权清理、重新确认、GC
  ├─ db.py           SQLite：记录 / 附件索引 / 下载任务 / blob 引用 / 审计事件
  ├─ store.py        内容寻址存储（CAS）：data/blobs/<sha256>
  ├─ downloads.py    在途下载任务的取消管理
  └─ web/index.html  采集页（并发下载、撤权、恢复、查历史）
demo.py              端到端复现"两记录共享内容、仅一个撤权"，36 项断言
```

## 运行

```bash
# 终端 1：慢速来源服务（每 16KB 延时 30ms，可复现"下载途中撤权"）
python3 source_server.py --port 8951

# 终端 2：采集端
python3 -m collector.app --port 8950 --source http://127.0.0.1:8951 --data ./data

# 浏览器打开采集页
http://127.0.0.1:8950

# 或者一键跑完整复现场景（自动起停两个服务并断言全部不变量）
python3 demo.py
```

## 数据模型与引用关系

- `records`：外部记录元数据 + `authorized` + `auth_epoch`（授权纪元）。
- `attachments`：每记录的附件索引，`blob_hash` 是指向 CAS 的**显式引用**。
- `tasks`：下载任务，与记录、附件关联。
- `blobs`：内容寻址存储，一份内容只存一次；`refcount` 为引用计数。
- `events`：审计/历史。

两条记录可引用同一 blob（共享内容省空间）；撤权只解除该记录自己的引用，
不影响其他记录——按记录存副本撤权简单但费空间，本方案用显式引用兼得两者。

## 关键语义

| 场景 | 行为 |
|---|---|
| 撤权 | `auth_epoch+1` 使旧预览/下载链接立即 410；附件引用解除；在途任务取消 |
| 下载途中撤权 | 工作线程按块检查取消标志，删除 `.part` 临时数据，只留任务状态与审计事件 |
| 撤权后取正文 | 预览/下载入口校验 epoch + 授权位 + 发布状态，一律 410/409 |
| 重新授权 | 附件进入 `unconfirmed`，**旧缓存不直接发布**；须经"重新确认" |
| 重新确认 | 拉来源最新元数据：哈希一致才允许复用 CAS（记 `cache_reuse_confirmed`），否则重新下载并校验 sha256 |
| 内容替换 | 同步发现来源哈希变化 → 附件 `stale`，重新下载后换引用，旧 blob 待 GC |
| GC | 按 `attachments` 表**重算**引用计数后，仅删除无引用 blob，绝不误删共享内容 |

## 复现场景（demo.py）

1. 两条记录并发下载全部附件 → 共享内容只存一份（refcount=2）；
2. 来源替换 rec-a 独有附件 → 重新下载途中撤权 rec-a → 任务中止、临时数据清除、
   rec-a 预览/旧下载入口 410，rec-b 的共享附件不受影响；
3. GC → rec-a 旧独有内容被回收，共享内容因 rec-b 引用保留；
4. 重新授权 rec-a → 缓存不直接发布（409）→ 重新确认后共享内容复用、
   被替换附件下载新版本，refcount 恢复为 2。
